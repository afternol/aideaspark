- R11ではほぼ全件「修正不要」となり、データ品質は高い状態に到達

### 新たに発見したハルシネーションパターン

#### K. 数値は正しいが出典機関が誤っているパターン
- DataGuard `problem`：「警察庁・JNSA調査では1,000万円超の被害が全体の50%」
  - 50%という数値は警察庁調査（令和6年）で確認できたが、JNSAにその数値は存在しなかった
  - 2つの機関をカンマで並列表記すると、数値の根拠がどちらか不明になる
- **対策**: 数値に紐づく出典は「機関名（調査名・年度）」で一対一対応で記載する

#### L. 競合サービスの導入実績が古い時点のまま残るパターン
- ケアブリッジ `competitiveEdge`：カナミックネットワークの導入件数が「40,500件超（2023年3月時点）」のまま
  - 実際は2025年9月時点で52,700件超に成長していた（30%以上の増加）
- **対策**: 導入件数・ユーザー数・会員数は特に陳腐化が早い。記述には時点（年月）を必ず付記すること

#### M. 副業者・フリーランス人口の数値ソースの混在
- フリ申告 `marketSize`：「副業者約332万人」→正しくは「副業がある者305万人（非農林業）」
  - 「フリーランス」「副業者」「副業希望者」「複業者」は定義が異なる。混在が誤りの原因
- **対策**: 副業・フリーランス系の数値は母集団定義（非農林業か全業種か、本業か副業か）をセットで記載

#### N. 「業界規模」が著しく過小評価されているパターン
- PetFresh `marketSize`：「数千億円規模」→実際は約2兆円（10倍近い過小評価）
  - ペット関連市場は矢野経済研究所2025年8月発表で1兆9,108億円（2024年度）
- **対策**: 「数千億円規模」などの概算表記は、実際の市場が1兆円以上の場合「1兆円超」と区別して表記する

#### O. 存在確認できない競合サービスが残るパターン
- スペアハウス `competitors`：「WeShare（ウィーシェア）」
  - 検索で同名の社宅シェア専業サービスが見つからず削除
- クローゼット回遊 `competitors`：「ラクサス」
  - ラクサスはブランドバッグ専門（衣類ではない）のため文脈が不適切
- **対策**: competitors に記載するサービスは①現在稼働中か②文脈（対象商材・顧客）が一致するかの2点を必ず確認

#### P. 根拠数値の削除が不徹底なパターン
- クローゼット回遊 `problem`：「70%以上の服を年1回以下しか着ない」
  - 業界で広く流通しているが、一次ソース（公的統計・主要調査機関）が確認できない
  - 数値を削除し「多くの服をほとんど着ていない」という定性表現に修正
- GrantFinder `problem`：「年間2,000件以上」→実態は数万件規模（スマート補助金で約30,000件収集）
- **対策**: 一次ソースが確認できない具体的数値は定性表現に置き換えることが正確性向上につながる

## アイデアDBファクトチェック監査（2026-04-27）

### 実施概要
- 対象: Ideaテーブル 全100件のビジネスアイデア（全フィールド）
- 期間: 第1〜13回・延べ13ラウンド、累計約344件の修正
- 手法: 10エージェント並列 × WebSearch × Supabase直接UPDATE
- 目的: ハルシネーション・事実誤認・誇張表現の排除

---

### 実施手法（再現可能な標準プロセス）

#### 1. 並列エージェント設計
- 100件を10件ずつ10グループに分割し、10エージェントを同時起動
- 各エージェントに同一の検証観点・UPDATE構文・報告フォーマットを指定
- 1ラウンドで全100件を網羅、所要時間は並列実行で約5〜10分

#### 2. エージェントへの指示テンプレート（重要）
```
## ハルシネーション排除の観点
- 出典不明の具体的数値（%・万人・億円）をWebSearchで一次ソースまで遡って確認
- 根拠なき断言の実態確認
- 競合サービスの機能・料金・現状（廃止・統合・料金変更）
- 法規制・義務化の正確な施行状況
- 「急増」「唯一」「最大」などの断言表現の根拠
- 企業名・サービス名の正式名称（旧名・略称の誤用）
- WebSearchで裏付けが取れない主張は削除・修正
```

#### 3. DB直接UPDATE構文
```javascript
import pg from 'pg';
const pool = new pg.Pool({ connectionString: 'postgresql://...' });
await pool.query(
  'UPDATE "Idea" SET "フィールド名" = $1, "updatedAt" = NOW() WHERE number = $2',
  [新しい値, 番号]
);
await pool.end();
```

#### 4. 報告フォーマット
- 修正あり: `#番号 フィールド名: 旧値→新値（理由・出典URL）`
- 修正なし: `#番号: 確認済み（検証した主要ポイントと出典）`

---

### 発見された誤りのパターン分類

#### A. 廃止・終了済みサービスの混入（最多・最重大）
競合として記載されているサービスが実際にはすでに終了している。
- SEND（2022年破産）、Quotta（2025年終了）、LINEヘルスケア（2025年6月終了）
- FiNC（2026年9月終了）、カメカリ（2023年1月解散）、ぐるなび仕入モール（2023年4月終了）
- **対策**: competitors フィールドは定期的に稼働確認が必要

#### B. 「義務化」「必須」の誤用
任意・推奨・ガイドラインを「義務化」と断言するパターン。
- Scope3開示「義務化」→ SSBJ基準は2027年3月期以降段階的、現時点は義務ではない
- サプライチェーン人権DD「義務」→ 経産省ガイドラインは任意
- EAP投資「義務に近い」→ 任意の取り組み
- インボイス確認「義務化」→ 「仕入税額控除の実務上必須要件」が正確
- **対策**: 法的根拠（法律名・条文・施行日）を必ず一次ソース確認

#### C. 出典不明の具体的数値
一次ソースまで遡れない数値が事実であるかのように記述されているパターン。
- 食材ロス率「15〜30%」→ 農水省調査「3〜5%」（10倍近い過大計上）
- 公立小中高教員「約90万人」→ 令和5年度文科省調べ「約66万人」（35%過大）
- 「93〜95%の AI 肌解析精度」→ 根拠なし（削除）
- **対策**: 数値は必ず「出典名・調査年月」をセットで記載。なければ削除

#### D. 時系列の誤り・古いデータの混入
新しいデータと古いデータを混在させて比較するパターン。
- ケアFit「介護離職率12.4%は全産業平均14.2%を下回る」→ 14.2%は2022年の古いデータ。2024年の全産業平均は約11.5%で**介護が上回っていた**（方向が逆転）
- NISA口座数「2,559万」→ 金融庁公式「2,560万4,058口座」（速報値と確定値の混用）
- **対策**: 統計は調査年・公表日・改定有無を必ず確認

#### E. 企業名・サービス名の誤記
正式名称・ブランド統合後の名称を把握していないパターン。
- 「HiPro Biz」→「HiPro Direct」（HiPro Bizは別の経営幹部向けサービス）
- 「SPEEDA・FORCAS統合」→ INITIAL も含む3ブランドが「スピーダ」に統一（2024年7月）
- OLGA「GVAブランド全体から改名」→「製品名GVAをOLGAへ変更、会社名GVA TECHは不変」
- LegalOn「旧LegalForce」→ 製品名LegalForceは現在も提供継続
- LIQUID「株式会社Elements」→ 正式社名は「株式会社ELEMENTS」（全大文字）
- **対策**: M&A・リブランド・社名変更は頻繁。最新プレスリリースを確認

#### F. EU規制スケジュールの誤り
CSDDDなど欧州規制は改正が重なり日程が複雑。
- EU CSDDD: Omnibus I（EU 2026/470・2026年3月18日発効）により加盟国転置期限は**2028年7月26日**、全企業適用開始は**2029年7月26日**に変更
- 旧スケジュール（2027/2028/2029年段階適用）を参照し続けていた
- **対策**: EU法は官報（Official Journal）の一次テキストを確認。法律事務所の解説（DLA Piper, Covington等）を参照

#### G. 競合サービスの機能・料金の陳腐化
競合説明が古い料金・機能情報に固定されているパターン。
- Design Pickle: 旧ティア制廃止→2025年6月に新モデル（Base $119+Creative Hours）へ移行
- Penji: 「$99〜」→「$499〜$1,497/月」の3段階に変更
- ビザスクlite: 謝礼「5万円程度」→「下限1.5万円（税抜）、種別ごとに15,000〜80,000円」
- クボタ農機シェアリング: 「業者型のみ」→ 農家オーナー機能も提供済み
- airCloset: 会員数「140万人」→「140万人超・有料会員40,209人」（訂正後も粗さあり）
- **対策**: 価格・機能情報は最低6ヶ月ごとに再確認

#### H. 法令・制度名の誤り
正式名称・根拠条文を誤っているパターン。
- 「医療機器リユース制度」→「単回使用医療機器再製造制度」
- 道路運送法「78条3号」（日本版ライドシェア）→「78条2号」（自家用有償旅客運送）が正しい根拠条文
- 「J-Innovation Platform」→「J-Innovation HUB」（経産省公式名称）
- かかりつけ医「行動変容を政策的に推進する制度」→「医療機関が機能を都道府県に報告する制度」
- **対策**: 制度名は省庁公式サイトの一次情報のみ参照

#### I. 統計の対象範囲・母集団の誤り
数値は正しいが対象範囲を誤って引用するパターン。
- 副業希望者「正社員の約2倍」→「有業者全体の241万人→493万人」（対象が有業者全体、正社員限定ではない）
- ケアFit「離職率12.4%は全産業平均を下回る」→ 使った全産業平均が2022年の古いデータで比較が無効
- **対策**: 数値の分子・分母・調査対象・調査年を必ずセットで確認

#### J. 因果関係・誇張表現の混入
「だから成長している」という因果が証拠なく断言されているパターン。
- 副業「急速に増加」→ 実施率はほぼ横ばい（約2.5%）、希望者が増加しているだけ
- 産学連携「急増・大幅拡充」→ 根拠となる統計未確認
- 「CtoCの農機貸借手段がほぼない」→ AGRICOM（2020年〜）が存在した
- **対策**: 「急増」「唯一」「ほぼない」は必ずファクトベースで根拠を要求

### 監査の教訓・改善提言

1. **アイデア生成時にWebSearch必須化**: 生成段階でリアルタイム検索を組み込めば初期品質が大幅向上
2. **competitors は生成後即時確認**: 「廃止済みサービスを競合に書く」は最多ミス。サービス稼働確認APIや定期バッチが有効
3. **数値には必ず出典注記を**: 生成AIは出典なしに数値を混入させやすい。「数値を書くなら出典を書く」をルール化
4. **法規制フィールドは更新トリガーを設ける**: 義務化・施行日・適用範囲は変わる。法改正ニュースをトリガーに自動フラグ立てを検討
5. **competitors フィールドは6ヶ月ごとに再生成推奨**: 競合状況は最も陳腐化が早い。定期自動更新の仕組みが必要
6. **「義務化」「唯一」「急増」はハルシネーションのシグナル**: これらのキーワードが含まれるフィールドを優先的にファクトチェック
7. **EU規制は一次テキスト確認を徹底**: 改正が重なる規制は法律事務所の最新解説を一次ソースとして扱う

## エクスポート

### html2canvasはTailwind v4のoklch/lab色を解析できない（2026-04-04）
- **状況**: カスタマイズ版のPDFエクスポートで `html2canvas` が `Attempting to parse an unsupported color function "lab"` エラー
- **原因**: Tailwind v4は内部で `oklch()` / `lab()` 色関数を使用。html2canvas 1.4.1はこれらに非対応。ページ内のDOM要素をキャプチャする際、親要素から継承されるTailwindのCSS変数が解析に失敗する
- **解決**: `iframe` を使って完全に隔離した環境を作成。iframe内にTailwind CSSが一切漏れない純粋なHTMLドキュメント（hex色のみ）を書き込み、その `body` をhtml2canvasでキャプチャ
- **教訓**: html2canvasを使う場合、親ページのCSSフレームワークの色形式に注意。最新CSSカラー関数（oklch, lab, lch等）は非対応。iframe隔離が安全策

### PDFのページ境界で文字が切れる問題（2026-04-04）
- **状況**: jsPDFで複数ページのPDFを生成すると、297mm間隔の機械的スライスでテキストの途中で切断される
- **解決**: キャンバスのピクセル行をスキャンし、改ページ候補位置の前後±40mm範囲で「最も白い行」（セクション間の空白）を探してそこで分割。各スライスを個別キャンバスに切り出してPDFに配置。2ページ目以降は上部に8mmマージン追加
- **教訓**: html2canvas + jsPDFの複数ページ出力では、単純な固定高さスライスは使えない。空白行検出アルゴリズムを入れることでテキスト切れを防止できる

### Word出力にはdocxライブラリが最適（2026-04-04）
- **状況**: クライアントサイドでWord文書を生成する必要があった
- **選定**: `docx` ライブラリ + `file-saver`。テキストとしてコピー・編集可能なネイティブ.docxを生成
- **注意点**: `file-saver` には `@types/file-saver` の型定義が別途必要（ないとNext.jsのビルドでType error）
- **教訓**: PDF（画像ベース）とWord（テキストベース）は別々の生成ロジックが必要。Wordはdocxライブラリで構造化ドキュメントを直接組み立てるのが最もクリーン

### ツールチップの z-index 問題（2026-04-02）
- **状況**: トレンドヒートマップのタイルにホバーで表示されるツールチップが、隣接タイルに隠れて読めない
- **原因**: `flex-wrap` で複数行になるタイル群で、後の行のタイルが前の行より z-index が高くなるため、上に表示するツールチップが被る
- **解決**: タイル自体に `hover:z-50`、ツールチップに `z-[100]` を付与。Tailwind の `group/name` でネスト対応
- **教訓**: `position: relative` な要素が並ぶ場合、ツールチップは要素単体の z-index だけでなく、hover 時に親のスタッキングコンテキストを引き上げる必要がある

### ブックマーク（localStorage）vs コレクション（DB）の二重管理（2026-04-02）
- **状況**: カード上の保存ボタンが `useBookmarkStore`（localStorage）で、コレクション機能は API 経由で DB に保存。2つが別系統で同期しない
- **解決**: 全画面の保存ボタンを `AddToCollection` コンポーネントに統一。compact プロップでアイコンのみ表示に対応
- **教訓**: 「とりあえず localStorage で」の仮実装は、後から DB 版との統一コストが全コンポーネントに波及する。保存系機能は最初から永続化先を統一すべき

### エンゲージメントボタンはカード一覧にも出す（2026-04-02）
- **状況**: リアクション（いいね・気になる・参考になった）が詳細ページにしかなく、一覧から押せない
- **解決**: `IdeaSummaryCard` にリアクションボタンを埋め込み、API に種類別カウント + ユーザーリアクション状態を返す拡張を実施
- **教訓**: エンゲージメント導線は「見る場所 = 押せる場所」にする。一覧カードにアクションがないと詳細を開く動機が薄い

### 不要な情報の削除判断（2026-04-02）
- **状況**: アイデア詳細のタグ行に「難易度: 低/中/高」バッジがあったが、フィルター検索には使われておらず、6軸スコアで実質カバーされていた
- **解決**: 指摘を受けて即削除
- **教訓**: 表示項目は「ユーザーがその場で意思決定に使うか」で判断。飾りの情報はノイズになる

## フィルター・検索

### ランキングにもフィルターが必要（2026-04-02）
- **状況**: ランキングが全件一律表示で、自分の興味領域のランキングが見られない
- **解決**: 領域・対象業界・対象顧客の3軸 SearchableSelect フィルターを追加
- **教訓**: 一覧系ページには必ず「自分に関係あるものだけ見る」手段を用意する

### 比較ページの選択 UX（2026-04-02）
- **状況**: ドロップダウン式 SearchableSelect で比較対象を選ぶ UI が、アイデア数が多いと探しづらい
- **解決**: キーワード検索 + カード型ピッカーに変更。サービス名・カテゴリ・業界・タグで検索可能に
- **教訓**: 選択肢が多い場合、ドロップダウンよりカード型ピッカーの方が情報量（バッジ等）を提示でき探しやすい

## AI機能

### 汎用AIとの差別化を常に問う（2026-04-02）
- **状況**: AIアイデア壁打ち機能を検討した際、「ChatGPTと何が違うのか」と指摘を受けた
- **教訓**: BizIdea独自のデータ（トレンドスコア・6軸評価・構造化DB・閲覧履歴）を活用しない限り、汎用AIと同じ機能を作っても価値がない
- **原則**: AI機能は「考えて終わり」ではなく「プラットフォーム内のアクション（プラン生成・比較・コレクション保存）に繋がる」設計にする
- **実例**: AI検索は全アイデアDBをコンテキストに渡し、既存データに基づいたマッチングを行う。汎用AIにはできない精度

### AI検索のサジェストは万人向けにする（2026-04-02）
- **状況**: 初期サジェストが「AIエージェントを使った業務効率化ビジネス」等テック寄りだった
- **修正**: 「一人で始められるスモールビジネス」「リピート収益が見込めるストック型ビジネス」等、起業検討者なら誰でもピンとくる表現に
- **教訓**: サジェストはターゲット層の最大公約数的な関心事にする

### AIモデルはコスパで選ぶ（2026-04-02）
- Claude Haiku 4.5を採用（入力$0.80/1M、出力$4.00/1M）
- 構造化データからのマッチング＋JSON出力にはHaikuで十分
- 1回あたり約0.1〜0.2円、レスポンス1〜2秒

## 機能の取捨選択

### 再カスタマイズは選択中バージョンをベースにする（2026-04-04）
- **状況**: マイアイデアの「再カスタマイズ」ボタンが元アイデア詳細ページへのリンクだった。複数バージョンがあっても常にオリジナルからやり直しになる
- **解決**: マイアイデア画面内にインラインのカスタマイズフォームを追加。選択中のバージョン（`customIdeaId`）をベースにAPIリクエストを送信
- **教訓**: バージョン管理UIがある場合、アクション（再カスタマイズ・プラン生成等）は「今選択中のバージョン」に対して実行されるべき。別ページに飛ばすとコンテキストが失われる

### 「時期尚早」な機能は入れない（2026-04-02）
- **フォロー/フォロワー**: コミュニティが成熟する前にソーシャル機能を入れても使われない → 全削除
- **「やります」宣言**: エンゲージメントとして重すぎた → 削除し、軽いリアクション（いいね等）に集約
- **教訓**: 機能は「今のユーザー数・利用頻度で意味があるか」で判断。将来のための先行実装は負債になる

### プロフィール公開/非公開は最初から入れる（2026-04-02）
- プライバシー設定は後から追加すると既存ユーザーのデフォルトが問題になる
- 最初から`profilePublic: true`のデフォルトと切替UIを実装しておく

## レイアウト

### stickyが効かない時はoverflow-autoを疑う（2026-04-02）
- **状況**: 左サイドバーのstickyが効かない
- **原因**: 親の`<main>`に`overflow-auto`が設定されていた。stickyは最も近いスクロール可能な祖先に対して機能する
- **解決**: `overflow-auto`を削除。ページ全体のスクロールはbody側で行う

### 左右パネルの視覚的分離（2026-04-02）
- 背景色の差（左: bg-muted/30、右: 白）+ border-rで境界を明確にする
- 左サイドバーは画面端まで伸ばす（親レイアウトの余白を負マージンで打ち消し）
